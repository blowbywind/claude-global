다음 관점에서 현재 변경 사항을 리뷰하세요:

## 리뷰 체크리스트

1. **정확성**: 의도한 동작을 하는가?
2. **보안**: 입력 검증, 비밀 노출, 인증 우회 위험은?
3. **성능**: N+1 쿼리, 불필요한 루프, 동기 블로킹은?
4. **가독성**: 6개월 후의 내가 이해할 수 있는가?
5. **테스트**: 핵심 로직에 테스트가 있는가?
6. **컨벤션**: 프로젝트 규칙을 따르는가?

## 오버엔지니어링 점검 (변경/추가된 코드 한정)

변경 코드가 과잉 구현인지 의사결정 사다리 관점으로 점검한다 (karpathy-guidelines 참조):

- **불필요한 신규 코드**: 요청 범위 밖 기능·추측성 추상화·단일 사용처의 일반화가 있는가? (YAGNI)
- **중복**: 기존 유틸/패턴으로 될 일을 새로 작성했는가?
- **불필요한 종속성**: 표준 라이브러리·네이티브 기능·기존 종속성으로 될 일에 외부 패키지를 추가했는가?
- **과한 복잡도**: 50줄로 될 것을 200줄로 썼는가? 한 줄로 될 것을 풀어 썼는가?

단, **안전 코드(입력 검증·보안·예외 처리·접근성)는 축소 대상이 아니다** — 이를 "단순화"하라고 권고하지 말 것. 발견 시 아래 형식으로 보고하되 심각도는 보통 **Medium/Low**(기능이 정상 동작하면).

## 출력 형식

이슈별로:

```
[심각도] 파일명:라인번호
문제: [설명]
수정: [구체적 코드]
```

심각도: **Critical** (즉시 수정) / **High** (중요) / **Medium** (개선 권장) / **Low** (선택적)

이슈 없으면 "리뷰 통과 — 이슈 없음" 으로 종료.

리뷰 대상: $ARGUMENTS
